[5.1.0] 2026-07-18

🐞 Bug Fixes

  • PostProcessRendererFeature<T> and GLMapRendererFeature<T> (URP) now poll CheckMaterialVersion() every frame and recreate their material(s) when the version changes, matching the Built-In PostProcess<T> host. Previously, resizing a variable-size array property (for example a dither matrix) while using the URP renderer feature left the material with the old array size. No current map effect uses this yet, but GLMapRendererFeature<T> is now wired up the same way.
  • PostProcessRendererFeature<T>.Create(), SeparableRendererFeature<T>.Create(), and GLMapRendererFeature<T>.Create() no longer leak resources when Unity calls Create() again (which happens on every enable/disable, every Inspector edit anywhere in the feature, and after script reload — not just once). The render pass(es) are still rebuilt every time (needed since injectionPoint is baked into the pass constructor with no way to update it later), but now properly release their native resources first via the new PostEffectPass.ReleaseResources(). The material(s) are only (re)created when actually missing, instead of being unconditionally destroyed and reallocated on every unrelated property edit.
  • MapPass/RenderGraph_MapPass no longer create or own their material/backgroundMaterial — ownership moved to GLMapRendererFeature<T>, which now applies the same "recreate only when missing" rule described above. Also fixes a latent NullReferenceException risk in GLMapRendererFeature<T>.AddRenderPasses when the pass was null (for example, if Create() had bailed out due to a missing shader) — it now falls back to Create() the same way PostProcessRendererFeature<T> does.
  • Added PostEffectPass.ReleaseResources() to release the pass's CommandBuffer and RTHandle — neither was ever released when a pass was discarded, which happened on every Create() call regardless of the fix above.
  • Fixed FxUtils.UpdateMaterial: when shader is null, it now destroys the existing material before dropping the reference. Previously it just set the reference to null, leaking the material if a map's shader ever went from valid to null at runtime.
  • FxUtils.CreateMaterial's non-URP branch now sets hideFlags = HideFlags.DontSave on the material it creates, matching every other material-creation site (the URP branch already got this for free from CoreUtils.CreateEngineMaterial).
  • Added MapRenderer<T> (Built-In) OnValidate, so map property edits refresh the material reactively instead of only on OnEnable/the manual Rebind button. Also wired CheckMaterialVersion polling into CreateOrUpdateMaterials (called every frame from BuildCommandBuffer, matching PostProcess<T>/GLMapRendererFeature<T>) — no current map effect needs it yet, but the hookup is now consistent across all four hosts.
  • Fixed FloatMatrixGUI.DrawSizeControls: the +/− row/column buttons mutated the live FloatMatrix directly (correctly bumping SizeVersion), then called ApplyModifiedPropertiesWithoutUndo() against a SerializedObject buffer that predated the mutation — silently reverting SizeVersion back to its stale value and leaving MaterialVersion unable to detect the resize. Now calls serializedObject.Update() instead, which re-pulls the entire current object state (including SizeVersion) into the buffer. Also hardened FloatMatrixGUI.DrawChannelContents's preset-apply callback, which had no sync step at all, with the same Update() call.

[5.0.0] 2026-07-15

🎉 New Features

  • Added GridType enum (Hex / Rect) for use with grid-based effects such as Pixelate and Dither Grid Bias.
  • Added Interval — a serializable float range with Min, Max, Center, and HalfSize properties, and an editor drawer that supports both min/max and center/half-size display modes.
  • Added RGBMatrix — three FloatMatrix instances (one per channel) plus a shared All matrix, controlled by a Locked flag. Used by the Dither Grid Bias effect.
  • Added GamelogicFxSettings (URP, experimental) — a static settings class for pipeline-level configuration such as AllowedPostProcessCamera.
  • Pixelate effect and PixelateProperties now support a Hex grid type (pointy-top hexagonal cells) via the new GridType property.
  • Pixelate now supports a Grid Angle property (±90°, inspector slider) to rotate the pixel grid, for both rect and hex modes. Rect mode now uses the same 9×9 jitter antialiasing as hex mode, with the rotation correctly applied in screen-pixel space.
  • Pixelate pixel grid is now anchored to the screen centre rather than the corner, so the grid is symmetric around the render target regardless of pixel size or rotation angle.
  • Added hex and rect grid conversion functions to Gamelogic.hlsl: pointy_hex_world_to_grid, pointy_hex_grid_to_world, and rect_world_to_grid.

⚙️ Editor Improvements

  • Added FloatMatrixGUI — a reusable editor GUI helper for drawing FloatMatrix fields with resize controls.
  • Added RGBMatrixPropertyDrawer — property drawer for RGBMatrix with per-channel tabs (All / R / G / B).
  • Added IntervalPropertyDrawer — property drawer for Interval supporting both min/max and center/half-size display modes.
  • Added GridTypeDrawer — property drawer for GridType that renders as inline toolbar buttons (Rect / Hex) instead of a dropdown.
  • Added StringDropdownPopup — a reusable editor utility for string selection dropdowns.

[4.0.0] 2026-05-16

🎉 New Features

  • Added updateCameraEachFrame to MapRenderer so maps can render correctly when source camera properties change.
  • Added SourceCamera to MapRenderer so maps can render correctly when the source camera changes to a different one.
  • Added MapProperties to MapRenderer so map properties can be modified by script.
  • Added setter properties on subclasses of MapRenderer to allow modifying them by script.
  • Added CameraScope property to renderer features to give some control on which cameras to apply renderer features to.
  • Added PixelOffset to PixelateProperties, allowing the pixel grid to be shifted in screen pixels.
  • Added RenderDataExtensions with FindFeature<T>, FindRequiredFeature<T>, and FindFeatures<T> extension methods on ScriptableRendererData for convenient renderer feature lookup by type.
  • Added ProceduralMaskedPostProcessRunner, a Built-In pipeline post-process runner that blends a stack of child effects using a procedurally computed mask — either a half-plane (line) or an ellipse — with configurable centre, angle, softness, invert, and radii parameters.

🐞 Bug Fixes

  • Fixed issues where maps where not handling renderer-specific issues correctly. This caused ID maps to render in only one color and UV maps to ignore tiling.

📄 Documentation

  • Improved documentation for map renderers.

💀 Breaking Changes

  • Removed CreateSimplePass from PostEffectRenderFeature.
  • Removed ExperimentalSettings.

[2.0.1] 2026-03-07

🐞 Bug Fixes

  • Fixed a bug in ShaderProperty.SetOn where the IntegerArray case wrote into floatArrayValue assuming it was non-null and the correct size, which could cause a NullReferenceException or IndexOutOfRangeException at runtime.
  • Fixed a bug in ShaderPropertyThrowHelper.WarnIfExceeds where the argName parameter was declared as int instead of string, causing incorrect formatting in warning messages.
  • Fixed a bug in FxUtils.DestroyMaterial (URP branch) where the parameter was named shader and the body referenced an undeclared variable materialToUpdate instead of the material parameter.
  • Fixed a typo in PropertyNotfoundException — renamed to PropertyNotFoundException to match .NET conventions. The old name is kept as an obsolete alias.
  • Fixed an inconsistent class name: GLNormalMapRenderer has been renamed to GLNormalMapRendererFeature to match sibling classes. The old name is kept as obsolete.

🔧 Engineering

  • Updated to Extensions 4.6.0.

📄 Documentation

  • Updated documentation fixing typos and other errors, and adding missing documentation.

⬆️ Upgrade Notes

  • PropertyNotfoundException is now PropertyNotFoundException. The old name is obsolete and will be removed in a future version.
  • GLNormalMapRenderer is now GLNormalMapRendererFeature. The old name is obsolete and will be removed in a future version.
